# NI, MAP, and RES voice architecture

NI accepts one bounded exact free-text query and grounds every result identity to the matching observed query. It explicitly rejects TOP ranked-headline intent and N feed/filter intent.

MAP means the world exchange-venue map, never IMAP or HMAP. Region, category and venue values must be exact current live identities. Status narration requires the venue timezone; a closed venue must include exact next-open local and UTC timestamps, so “Closed today” alone is never treated as useful completion.

RES is live-undocumented beyond opening a security-scoped research surface. It therefore exposes no invented nested search, filter, report-open, download or summarization action. Explicit report-list narration is permitted only from exact observed rows for the matching security. All three families remain runtime-disabled.
