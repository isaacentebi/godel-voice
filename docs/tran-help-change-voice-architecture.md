# TRAN, HELP, and CHANGE voice architecture

All three surfaces are read-oriented and dynamic. Their nested actions remain runtime-disabled until exact live identities and rendered postconditions are proven.

## TRAN

Current, Previous, and Next are not loose directions. Each request binds the currently loaded period ID to one exact destination period ID and label supplied by the live panel. Section and speaker navigation require one exact live identity. Text query is available only when Godel exposes a documented/live query control.

A quote or summary requires proof that the complete transcript for the exact period has loaded, including exact speaker turns and section names from `Godel TRAN panel`. Missing text, mismatched period identity, speaker ambiguity, or empty requested sections block narration. Quotes must reproduce supplied turns; summaries may synthesize only from those supplied turns.

The company-website link is external navigation. It requires explicit open/follow/visit language and the exact live HTTPS destination.

## HELP

Topics come from the current dynamic HELP index. A command topic carries an exact canonical Godel command code; non-command topics use `null`. Similar labels, guessed aliases, or unknown command codes block navigation. External HELP links require explicit intent and exact HTTPS identity.

## CHANGE

Entry selection binds an exact changelog ID, version, and title. Interactive command pills bind an exact live link ID to one canonical Godel command. Changelog narration requires exact current entries from `Godel CHANGE panel`; it does not invent features or release notes. External changelog links follow the same explicit-intent HTTPS gate.

Corrections supersede prior clauses. Direct contradictions and any unsupported clause block the complete compound step.
